# AI-звукарь для импров-шоу — план (ревизия 2)

> Исправленная версия исходного плана. Что изменено и почему — в разделе 0.

## Цель проекта

Создать систему, которая во время импровизационного шоу в реальном времени:

- видит происходящее на сцене через камеру;
- слышит реплики и звуки со сцены;
- понимает контекст сцены;
- ставит подходящие звуковые эффекты (сначала — предлагает, затем — автоматически только для проверенных случаев);
- при необходимости запускает музыку или атмосферу;
- предлагает момент для отбивки;
- в дальнейшем может управлять OBS, светом и другими элементами шоу.

Ключевой принцип: нейросеть не должна «пытаться быть смешной». Она работает как технический участник шоу и вмешивается только тогда, когда действие уже совершено актёрами и однозначно считывается.

Второй принцип: **живой техник всегда главнее AI**. Ручной пульт работает всегда — даже если упал интернет, API или модель.

## 1. Общая архитектура

```
Камера ──────────────┐
                     ├──> Multimodal Live AI ──> Cue Controller ──> Audio Engine ──> Микшер ──> Зал
Микрофоны ─> Микшер ─┤        (что)             (можно ли)          (когда/как)
   (aux без SFX)     │                              ▲
                     └──> Локальный быстрый слой ───┘   (fire-триггеры: ключевые слова, транзиенты)
                                                    ▲
                                       Пульт оператора (всегда главнее)
```

Части системы:

1. **Видео** — общий план сцены; кадры уходят модели ~1 раз в секунду (частота и разрешение подбираются на этапе 1).
2. **Аудио** — отдельная aux-шина микшера только с микрофонами актёров; передаётся модели в реальном времени.
3. **AI-модель** — понимает реплики и происходящее, выбирает действие, **не генерирует звук и не говорит** (вывод модели — только текст/function calls), вызывает только разрешённые функции.
4. **Локальный быстрый слой** (с этапа 2–3) — локальное распознавание ключевых слов и детектор резких звуков/хлопков. Не принимает решений сам — только срабатывает для уже «взведённых» cue.
5. **Cue Controller** — проверяет команды, применяет ограничения, ведёт лог.
6. **Audio Engine** — проигрывает предзагруженные звуки по каналам с ducking.
7. **Пульт оператора** — ручной запуск любого звука, подтверждение предложений, kill switch, кнопка «Новая сцена».

## 2. Почему модель не управляет звуком напрямую

Модель выдаёт только структурированные команды; локальная программа решает, выполнять ли их.

```
play_sfx(cue, reason, confidence)        # cue — enum из реестра
arm_sfx(cue, trigger, reason, timeout)   # взвести эффект, сработает по триггеру
play_music(cue, reason, confidence)
play_ambience(cue, reason, confidence)
stop_music(fade)
suggest_scene_end(reason, confidence)    # только предложение, отбивку запускает человек
```

- `cue` — строго `enum` в схеме функции: модель не может вызвать несуществующий звук.
- `reason` — короткое описание увиденного/услышанного, обязательно (нужно для лога и разметки).
- `confidence` — `low | medium | high`; используется как слабый сигнал.

Это защищает от случайных повторов, нескольких SFX одновременно, слишком частых вмешательств, ложных отбивок и задержек из-за генерации звука.

## 3. MVP

### Входные данные

- одна камера (общий план, хорошо освещённая сцена);
- одна aux-шина со сцены без звуков самой системы;
- 15–20 заранее подготовленных звуков в WAV.

### Базовая библиотека

**SFX (канал `sfx`):** затвор фотоаппарата, дверной звонок, звонок телефона, удар, падение, автомобиль, сирена, касса, магический эффект.

**Громкие SFX (режим `confirm` по умолчанию):** выстрел, взрыв. Ложное срабатывание громкого эффекта — самая дорогая ошибка: пугает зал и навязывает актёрам действие.

**Музыка (канал `music`):** романтическая, тревожная.

**Атмосфера (канал `ambience`):** хоррор, офис, ресторан, дождь, улица.

**Отбивки (канал `sting`):** финальная отбивка.

Аплодисменты из MVP убраны: AI, «аплодирующий» сам себе или актёрам, воспринимается как закадровый смех и почти всегда лишний.

Музыка — только royalty-free или с лицензией на публичное исполнение.

### Что должна уметь модель

Актёр говорит:

> Смотрите сюда. Сейчас вылетит птичка.

…и изображает фотографа. Реплика звучит **до** действия — значит, модель может заранее взвести эффект:

```
arm_sfx("camera_shutter", trigger="next_transient_or_2s", reason="актёр готовится фотографировать")
```

Затвор срабатывает в момент «щелчка» (звук актёра, хлопок, ключевое слово «чик») или по кнопке оператора; если за таймаут ничего не произошло — cue снимается.

## 4. Cue Controller

Обязательная прослойка между AI и звуком. Единый реестр cue:

```yaml
channels:
  sfx:      { max_simultaneous: 1 }
  music:    { max_simultaneous: 1, duck_under: [sfx, sting], duck_db: -8 }
  ambience: { max_simultaneous: 1, duck_under: [sfx, sting], duck_db: -6 }
  sting:    { max_simultaneous: 1, stops: [music, ambience] }

global:
  min_gap_between_ai_cues: 3.0     # секунд между любыми AI-эффектами
  max_ai_cues_per_minute: 6
  min_confidence_auto: high

cues:
  camera_shutter:
    file: sfx/camera_shutter.wav
    channel: sfx
    mode: auto            # auto | confirm | off
    cooldown: 1.5
    max_repeat: { count: 5, window: 30 }   # не больше 5 раз за 30 секунд

  doorbell:
    file: sfx/doorbell.wav
    channel: sfx
    mode: auto
    cooldown: 5

  gunshot:
    file: sfx/gunshot.wav
    channel: sfx
    mode: confirm         # громкий — только через оператора
    cooldown: 10

  romantic:
    file: music/romantic.wav
    channel: music
    mode: confirm
    do_not_restart_if_playing: true
    fade_in: 2.0
    fade_out: 3.0

  scene_end:
    file: sting/scene_end.wav
    channel: sting
    mode: confirm         # AI только предлагает, запускает оператор
    cooldown: 30
```

Контроллер умеет:

- cooldown на cue и глобальный лимит частоты;
- ограничение повторов в скользящем окне;
- каналы, приоритеты, ducking, взаимоисключения;
- режим cue: `auto` / `confirm` / `off` — переключается на лету;
- снимать «взведённые» cue по таймауту и при смене сцены;
- игнорировать команды, пришедшие с опозданием (например, > 2.5 с от момента кадра/аудио, на которых основано решение);
- логировать каждое решение, включая причину блокировки;
- kill switch: одной клавишей отключить всю автоматику, ручной пульт продолжает работать.

## 5. Системная инструкция для AI

```
Ты технический звукорежиссёр импровизационного шоу. Ты не говоришь и не
комментируешь — только вызываешь функции или ничего не делаешь.

Ставь эффект, только когда действие или ситуация однозначно считываются
из происходящего на сцене. Эффект усиливает уже совершённое актёрами
действие и не придумывает новое за них: каждый звук в импрове — это
предложение, которое актёры будут вынуждены принять.

Если не уверен — ничего не делай. Бездействие — нормальный и частый ответ.

Не реагируй на:
- упоминания без действия («надо бы позвонить маме» — это не звонок);
- отрицание и гипотетику («хорошо, что не было взрыва»);
- смех и реакцию зала;
- звуки и музыку, которые ты сам запустил.

Если актёр сам озвучивает эффект голосом («дзынь-дзынь!») — обычно не
дублируй его.

Не ставь эффекты часто. Не пытайся шутить поверх актёров.

В поле reason коротко опиши, что именно ты увидел или услышал.
```

## 6. Работа с отбивками

Отбивка сложнее обычного SFX. Модель должна оценить:

- был ли сильный панч;
- закончилась ли смысловая линия;
- есть ли естественная пауза;
- не разрушит ли продолжение уже возникший момент.

Функция: `suggest_scene_end(reason, confidence)`.

AI не заканчивает сцену сам:

```
AI считает, что сцену пора закончить
        ↓
загорается индикатор у техника (и, по желанию, у ведущего)
        ↓
техник подтверждает (Space) или игнорирует
        ↓
звучит отбивка
```

Подсказка гаснет сама через несколько секунд, если её не подтвердили, — чтобы техник не нажал на «протухшее» предложение.

Переход к автоматической отбивке — только после того, как по статистике нескольких шоу доля «perfect» стабильно высокая, а «too early» близка к нулю. Скорее всего, для отбивок режим `confirm` останется навсегда: это художественное решение команды.

## 7. Инструкция для определения конца сцены

```
Предлагай завершить сцену, только если:
1. произошёл сильный комедийный панч;
2. после него появилась естественная пауза (зал смеётся, актёры не
   продолжают линию);
3. дальнейшее развитие скорее ослабит момент;
4. либо история очевидно получила завершение.

Не предлагай завершение:
- просто из-за молчания;
- из-за случайной паузы;
- потому что сцена долго идёт;
- если актёры продолжают активно развивать новую идею.
```

Смех зала здесь полезен как сигнал — поэтому для отбивок модели нужен **отдельный** слабый сигнал громкости зала (уровень с зального микрофона), а не сам зальный звук в общем потоке.

## 8. Технический стек

### Компьютер

Windows-ноутбук, проводной интернет (Wi-Fi площадки ненадёжен) + резервный 4G/5G-модем.

### Программа

Python (asyncio): клиент realtime-API, контроллер, аудиодвижок, веб-интерфейс оператора на localhost.

### Видео

USB-камера или камера через карту захвата; позже — виртуальная камера OBS. Учесть сценический свет: веб-камеры плохо работают с контрастными пятнами прожекторов — нужна ручная экспозиция.

### Аудио

```
микрофоны актёров
   ↓
микшер
   ├──> main ──> колонки (сюда же — выход ноутбука)
   └──> aux (pre-fader, только микрофоны актёров) ──> аудиоинтерфейс ──> AI

зальный микрофон ──> только индикатор громкости зала (для отбивок)
```

Выход ноутбука идёт в микшер **отдельным каналом**, который не попадает в aux для AI.

### AI

Кандидаты: Gemini Live API, OpenAI Realtime API. Что проверить на этапе 1 для каждого:

- приём аудио и изображений в одной сессии;
- function calling во время стрима и задержка до вызова функции;
- режим «без голосового ответа» (только текст/вызовы функций);
- ручное управление ходами при непрерывной речи на сцене;
- максимальная длительность сессии, переподключение, восстановление контекста;
- стоимость часа работы (аудио + кадры).

### Проигрывание звука

- только WAV, предзагрузка в память при старте;
- вывод через WASAPI (exclusive) или ASIO;
- никакой генерации SFX нейросетью во время шоу.

## 10. Логирование

Лог — JSONL, одна запись на решение:

```json
{
  "show_id": "2026-10-10",
  "scene_id": 4,
  "t_media": 812.4,
  "t_sent": 812.6,
  "t_tool_call": 813.9,
  "t_played": 813.95,
  "cue": "camera_shutter",
  "call": "play_sfx",
  "reason": "актёр изображает фотографа, говорит 'сейчас вылетит птичка'",
  "confidence": "high",
  "result": "played",
  "blocked_by": null,
  "operator_label": "correct"
}
```

`result`: `played | suggested | confirmed | blocked | expired | late_dropped`.

Таймстемпы позволяют разложить задержку по звеньям: захват → отправка → ответ модели → воспроизведение. Параллельно пишется видео + аудио прогона с тем же таймкодом.

## 11. Feedback loop и replay-стенд

После прогона оператор размечает решения (удобнее — по видеозаписи с метками решений на таймлайне):

- правильно;
- неправильно;
- слишком рано;
- слишком поздно;
- хороший эффект, но лишний;
- пропущенный эффект (метка ставится на таймлайне вручную).

Как использовать разметку:

- **Не копировать сырые примеры в промпт** — он раздувается, это увеличивает задержку и стоимость, а текстовое описание не передаёт видео. Вместо этого из ошибок выводятся **короткие правила** («звук телефона только при жесте трубки у уха»), а лучшие 5–10 примеров — в few-shot.
- Ошибки по конкретному cue в первую очередь чинятся режимом и лимитами контроллера, а не промптом.

**Replay-стенд:** записанный прогон подаётся в систему как живой поток. Любое изменение промпта, модели или порогов прогоняется на всех записях, метрики сравниваются с предыдущей версией. Это главный инструмент разработки — без него каждое улучшение требует живых актёров.

## 12. Этапы разработки

### Этап 1 — Proof of Concept

Цель: проверить, что AI понимает сцену, и измерить реальную задержку.

- камера + aux-аудио + realtime-API;
- предложения выводятся текстом с таймстемпами, без воспроизведения;
- запись прогона для replay;
- сравнение 2 провайдеров по чек-листу из раздела 8;
- проверка: отвечает ли модель вовремя при непрерывной речи на сцене.

### Этап 2 — MVP Soundboard

- 15–20 SFX в WAV, предзагрузка;
- function calling с enum cue;
- Cue Controller: cooldown, лимиты, каналы, лог;
- **ручной пульт, kill switch, кнопка «Новая сцена»** (сброс контекста, ввод подсказки зала);
- все cue в режиме `confirm`; в `auto` переводятся по одному после проверки на replay.

Цель: полноценный прогон, на котором техник не теряет контроль.

### Этап 3 — Human-in-the-loop + быстрый слой

Интерфейс техника:

```
[ CAMERA SHUTTER ]  high   "изображает фотографа"   [PLAY]  (гаснет через 4 с)
[ SCENE END ]       medium "панч + смех зала"        [PLAY]
```

- `arm_sfx` + локальные fire-триггеры (ключевые слова, транзиенты);
- очевидные SFX — `auto`, громкие и отбивки — `confirm`.

### Этап 4 — AI-звукарь

- музыкальные подложки и ambience;
- fade in / fade out, ducking;
- автоматическая громкость относительно уровня сцены;
- автоопределение начала новой сцены (как подсказка оператору).

### Этап 5 — AI-техник

OBS, свет (DMX — только через предустановленные сцены, никаких «сырых» каналов от модели), проектор, титры, автоматическая запись шоу.

## 13. Главный технический риск — задержка

Для комедии критично время. Реалистичная картина при прямом вызове:

```
0.0 с  — действие актёра
0–1.0  — ожидание следующего кадра (1 fps) / накопление аудио
~0.3   — сеть до API
0.5–1.5 — модель формирует вызов функции
~0.05  — контроллер + запуск предзагруженного WAV
───────
итого ~1–3 с
```

Поэтому эффекты делятся на два класса:

1. **Реактивные** (атмосфера, музыка, звонок в дверь «в ответ» на «кто-то пришёл») — допускают 1–2 с, ставятся прямым вызовом.
2. **Мгновенные** (затвор, удар, падение) — задержка больше ~0.3 с убивает шутку. Схема **arm → fire**: модель по контексту заранее «взводит» cue, а срабатывает он по быстрому локальному сигналу (хлопок/транзиент, ключевое слово, кнопка/педаль оператора). Если взведения не было — для мгновенных эффектов лучше пропустить, чем опоздать.

Метрики, которые измеряются отдельно (из таймстемпов раздела 10):

- задержка захвата аудио и видео;
- сеть до API;
- время до function call;
- время от команды до звука в колонках;
- доля команд, отброшенных как опоздавшие.

---

## 14. Принцип: звук локальный, момент — локальный

AI определяет **ЧТО** уместно сейчас.
Локальная система определяет, **МОЖНО ли** (контроллер) и **КОГДА ТОЧНО** (fire-триггер или оператор) это сыграть.

Звуковые файлы заранее загружены в память — эффект запускается за миллисекунды после разрешения.

## 16. Первый реальный эксперимент

Нужно:

- ноутбук, камера, aux со сцены (или один микрофон, **не** слышащий колонки);
- 15–20 звуков;
- Python;
- Gemini Live и/или OpenAI Realtime;
- запись видео + аудио с таймкодом.

Тест:

1. сыграть 2–3 сессии по 10–15 минут импровизации;
2. не сообщать AI заранее, какие события произойдут;
3. живой техник параллельно работает как обычно — его действия логируются как эталон;
4. AI работает в режиме «только предлагать» (звук не идёт в зал);
5. после прогона разметить решения AI и пропуски;
6. посчитать метрики раздела 17;
7. сохранить записи для replay-стенда.

## 17. Критерии успешного MVP

Ориентировочные пороги (уточнить после первого эксперимента):

| Метрика | Цель MVP |
|---|---|
| Точность (доля правильных среди сыгранных/предложенных) | ≥ 80 % |
| Полнота по «очевидным» SFX из библиотеки | ≥ 60 % |
| Медианная задержка реактивных эффектов | ≤ 1.5 с |
| Задержка мгновенных эффектов при arm → fire | ≤ 0.3 с |
| Ложные громкие эффекты | 0 за шоу |
| Ложные AI-эффекты в зал | ≤ 2 за час |
| Вмешательства оператора (kill/отмена) | ≤ 3 за час |
| Обрывы сессии без автоматического восстановления | 0 |

И качественные критерии: AI умеет ничего не делать в неоднозначной ситуации, система не отвлекает актёров и зрителей.

Главная задача первого прототипа — не автономность, а проверка, может ли AI быть аккуратным техническим партнёром импров-команды.

## 18. Риски и эксплуатация

- **Сеть.** Проводное подключение + резервный модем. При потере связи система сама переходит в ручной режим, на пульте — заметный индикатор.
- **Отказ API.** Ручной пульт не зависит от AI. Шоу никогда не должно зависеть от облака.
- **Стоимость.** Непрерывный поток аудио + кадров тарифицируется по токенам — посчитать стоимость часа на этапе 1 и выбрать частоту кадров/разрешение.
- **Приватность.** Видео зала и сцены уходит в облако: камера направлена только на сцену, зрителей предупредить (афиша/объявление), проверить политику провайдера по хранению данных.
- **Лицензии.** Музыка и SFX — с правом публичного исполнения.
- **Громкость.** Лимитер на выходе ноутбука; громкие cue — только `confirm`.
- **Актёры.** Команда заранее знает, что в зале AI-техник и как он реагирует (например, «птичка» взводит затвор), — это часть договорённостей, как с живым техником.
