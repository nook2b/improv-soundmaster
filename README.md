# improv-soundmaster

AI-звукарь для импров-шоу. План проекта — [PLAN.md](PLAN.md).

**Сейчас готово:** прогон записей в теневом режиме с отчётом; распознавание речи на Mac;
правила по словам; облачная модель (OpenAI / Gemini) с бюджетом; детектор «монтажа»;
ручной пульт в браузере, реестр звуков, проигрыватель с шинами
(эффекты, музыка, атмосфера, отбивки), приглушение музыки под эффекты, лимитер, музыка из файлов
или генератора с автоматическим переходом на файл при сбое, запись входа и выхода, журнал всех
действий. Контроллер уже содержит правила для будущих команд AI (подсказки, лимиты, устаревание,
запрет автозапуска громких эффектов), но сам AI ещё не подключён.

## Установка на Mac

Нужен Python 3.11 или новее (`python3 --version`; установить — с python.org или `brew install python`).

```bash
git clone https://github.com/nook2b/improv-soundmaster.git
cd improv-soundmaster
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[files,dev]"
```

**Доступ к микрофону.** При первом запуске macOS спросит, можно ли Терминалу использовать
микрофон, — разрешите. Если вход молчит: Системные настройки → Конфиденциальность и безопасность →
Микрофон → включить для Терминала (или iTerm/VS Code).

## Установка на Windows (для разработки и проверок)

Всё, кроме распознавания через MLX (оно только для Mac), работает и на Windows.

```powershell
winget install Python.Python.3.12 Git.Git Gyan.FFmpeg yt-dlp.yt-dlp
git clone https://github.com/nook2b/improv-soundmaster.git
cd improv-soundmaster
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -e ".[files,asr-cpu,dev]"
python -m soundmaster replay "путь\к\сцене.mp4" --asr faster
```

Распознавание на Windows — `--asr faster`: с видеокартой NVIDIA быстро (можно `--asr-model large-v3-turbo`),
на одном процессоре — медленнее (модель `small` по умолчанию). Камера на Windows — через DirectShow:
имя из `python -m soundmaster cameras` впишите в `video.camera`. Ключи API в PowerShell:
`$env:OPENAI_API_KEY="sk-..."`.

На шоу рекомендуется Mac M2: распознавание через MLX быстрее, а основная проверка — на нём.

## Первый запуск

```bash
source .venv/bin/activate
python -m soundmaster import-sounds ПАПКА  # ваши звуки: имя файла = id из реестра (doorbell.mp3 …)
python -m soundmaster make-test-sounds   # тестовые звуки для того, чего ещё нет
python -m soundmaster devices            # список аудиоустройств
python -m soundmaster check              # проверить конфигурацию
python -m soundmaster run                # открыть пульт: http://127.0.0.1:8765
```

Остановка — `Ctrl+C` в Терминале.

Звуки в git не хранятся. `import-sounds` берёт файлы любых форматов (mp3, mp4, m4a, wav, flac …),
сопоставляет по имени с id эффекта или фона из `config/registry.yaml` (`doorbell.mp3` → эффект
`doorbell`), конвертирует в WAV, выравнивает громкость и у коротких эффектов срезает тишину в
начале. Уже существующие файлы не трогает (`--force` — заменить, например тестовые на настоящие).

Без звуковой карты и входа (проверить интерфейс): `python -m soundmaster run --null-audio`.

Домашняя проверка всего конвейера без правки `show.yaml` — флаги `run`:
`python -m soundmaster run --input brio-mic --asr faster --brain openai --camera "Logitech BRIO"`
(`--asr-model large-v3-turbo` — с видеокартой NVIDIA; имя камеры — из `cameras`).

## Домашний тест без рекордера

```bash
python -m soundmaster run --input mac-mic    # встроенный микрофон Mac
python -m soundmaster run --input brio-mic   # микрофоны веб-камеры Logitech Brio
```

Флаг `--input` меняет профиль входа только на этот запуск; `config/show.yaml` не трогается.
Если устройство не находится — `python -m soundmaster devices` и поправьте `device` в
`config/inputs/mac-mic.yaml` или `brio-mic.yaml`. Слушайте в наушниках, иначе микрофон
записывает и звуки системы из динамиков (так же, как рекордер на площадке).

## Подключение рекордера

1. Подключите рекордер к Mac по USB и включите на нём режим аудиоинтерфейса (у Zoom H4n/H5/H6 —
   «USB → Audio Interface»; у других моделей — по инструкции).
2. `python -m soundmaster devices` — найдите имя рекордера в списке.
3. В `config/inputs/recorder.yaml` впишите часть имени в `device`, например `device: "H5"`.
4. `python -m soundmaster run` — на пульте в разделе «Вход» должны двигаться уровни.

Рекордер слышит и актёров, и колонки. Поэтому в этой конфигурации эффекты AI только подсказывает на
пульте, а не запускает в зал сам. Музыка и атмосфера — автоматически (раздел `autonomy` в
`config/show.yaml`, см. «Автоматическая музыка» ниже).

## Вывод звука

По умолчанию — выход Mac, выбранный в системе. Другой выход: `output.device` в `config/show.yaml`
(часть имени из списка `devices`). Bluetooth-колонки не используйте: задержка сотни миллисекунд.

## Пульт

| Клавиша | Действие |
|---|---|
| `1`–`9`, `0` | эффекты (назначаются в `config/registry.yaml`) |
| `Q` `W` `E` `R` | музыка и атмосфера |
| `N` | новая сцена (поле «подсказка зала» — `Enter`) |
| `A` | автоматика вкл/выкл |
| `S` / `M` / `B` | подтвердить подсказку: эффект / музыка / отбивка |
| `X` | стоп AI-звук (и автоматика выкл) |
| `Esc` | стоп всё |
| `.` | отметка «здесь было событие» — для будущей разметки записей |

Пробел намеренно ничего не делает: в браузере он прокручивает страницу и нажимает кнопку в фокусе.
Горячие клавиши работают, только когда окно пульта активно.

## Свои звуки

Положите WAV в `sounds/` (например `sounds/sfx/doorbell.wav`) с теми же именами, что в
`config/registry.yaml`, или поменяйте пути и добавьте эффекты в реестре. Папка `sounds/` не
попадает в git — проверяйте лицензии сами (PLAN.md, разд. 12).

## Записи и журнал

Каждый запуск создаёт `recordings/<дата-время>/`:

- `input.wav` — все каналы входа (рекордер);
- `output_reference.wav` — то, что система отправила в колонки;
- `journal.jsonl` — все нажатия, решения, старты звуков с задержкой команда → звук.

Все времена — на одних часах, дорожки совмещаются по `t_first_sample` из журнала. Записи содержат
голоса актёров и зрителей: в git они не попадают, храните и удаляйте их по договорённости с командой.

## Прогон записей (теневой режим)

Запись сцены подаётся в систему «как вживую»: ничего не звучит, всё, что система сделала бы,
пишется в журнал и в наглядный отчёт `report.html`.

```bash
brew install ffmpeg                         # один раз: чтение видео
pip install -e ".[asr-mac]"                 # один раз: распознавание речи на M1–M4

python -m soundmaster replay ~/Movies/сцена.mp4 --asr mlx
```

Вместо файла можно дать ссылку (YouTube, Google Drive): нужен `brew install yt-dlp`, видео
скачается в `recordings/downloads/` (до 720p) и сразу прогонится:

```bash
python -m soundmaster replay "https://youtu.be/Zha1fA7l6gY" --asr mlx
```

Первый запуск скачивает модель распознавания (~1,5 ГБ, несколько минут). Без облачной модели
отчёт покажет: что распознано и с какой задержкой, как сработали правила по словам
(«птичка» → взвести затвор, «чик» → сработать) и детектор «монтажа».

С облачной моделью (ключ задаётся в Терминале на время сеанса, в файлы не попадает):

```bash
export OPENAI_API_KEY="sk-..."              # ключ: platform.openai.com → API keys
python -m soundmaster replay сцена.mp4 --asr mlx --brain openai

export GEMINI_API_KEY="..."                 # ключ: aistudio.google.com → Get API key
python -m soundmaster replay сцена.mp4 --asr mlx --brain gemini
```

В отчёте — ответы модели, задержки, токены и стоимость, пересчитанная на час. Бюджет на один
запуск — `brain.budget_usd` в `config/show.yaml` (по умолчанию $3): дальше запросы прекращаются.

Полезные флаги: `--max-seconds 120` (только начало), `--scene-cut AUTO` (монтаж сам начинает
новую сцену), `--no-video`, `--transcript файл.txt` (готовая расшифровка вместо распознавания,
строки `0:12-0:15 текст`), `--fast` (быстрее реального времени, без облачной модели).

## Слух и модель в живом режиме

В `config/show.yaml`: `listen.asr: mlx` — распознавание с входа (рекордер/микрофон), `brain.provider:
openai` или `gemini` — облачная модель, `video.enabled: true` — камера (`python -m soundmaster cameras`
покажет имя). На пульте появятся распознанные реплики, расход и задержка модели, её «заметка о сцене»,
взведённый эффект с кнопкой «Сработать» (`F`).

Как это устроено («каскад»): речь превращается в текст локально на Mac; простые правила по словам
работают сразу; облачная модель получает текст последних реплик, состояние сцены и иногда кадр и
отвечает строгим списком действий из реестра; контроллер решает, можно ли их выполнить.

## «Монтаж»: проход перед сценой

Детектор по камере замечает крупную фигуру, быстро проходящую через кадр, — сигнал новой сцены.
Режим `scene_cut.mode`: `AUTO` (по умолчанию) — сам начинает новую сцену (музыка прошлой сцены
гаснет, модель подбирает новую, когда поймёт сцену), `SUGGEST` — подсказка на пульте, `OFF`. Пороги — в
`scene_cut.detector`; подбираются по прогонам ваших записей (в отчёте видны все срабатывания).

## Будущее оборудование: петлички, микшер, аудиоинтерфейс

Вход описывается профилем в `config/inputs/`. Код менять не нужно — только строку
`input_profile` в `config/show.yaml`:

| Профиль | Когда |
|---|---|
| `inputs/recorder.yaml` | сейчас: рекордер у сцены |
| `inputs/lavaliers-interface.yaml` | 8 петличек → многоканальный интерфейс (Focusrite 18i20, Behringer UMC1820, MOTU) |
| `inputs/mixer-aux.yaml` | петлички → микшер, в Mac идёт отдельный выход только с актёрами + микрофон зала |

У каждого канала — роль: `stage_mix`, `actor_mic`, `actors_aux`, `room`, `reference`. Как только в
профиле появляется чистый звук актёров (`actor_mic` или `actors_aux`), программа сама начинает
отдавать AI именно его, а автозапуск допущенных эффектов становится возможным.

## Автоматическая музыка и потоковая генерация

Музыку AI ставит сам, без человека (`autonomy.music: AUTO` в `config/show.yaml`; `SUGGEST` —
вернуть подсказки на пульте). Модель не пишет описание музыки свободным текстом: она выбирает по
одному слову из словаря `music_vocabulary` в `config/registry.yaml` — жанр (нуар, вестерн, сказка,
триллер …), настроение, энергию, темп и состав (обычно «как в жанре»), — а программа собирает
из них запрос к генератору. Словарь
можно расширять, не меняя код. Правила:

- в начале шоу и сразу после «монтажа» играет нейтральная музыка (`autonomy.music_neutral`), а как
  только модель поймёт сцену (часто по 1–2 репликам), музыка плавно, за ~8 с, перетекает в
  выбранную; атмосфера прошлого места гаснет;
- первый выбор в сцене можно поправить через `autonomy.music_first_hold` секунд (10), дальше AI
  не меняет музыку раньше чем через `autonomy.music_min_hold` (30), чтобы она не «прыгала»;
- для разнообразия модель иногда выбирает один инструмент или маленький состав (только гитара,
  только фортепиано, струнный квартет …) — раздел `instruments` словаря; она видит музыку
  прошлых сцен и старается не повторяться;
- если музыку включил человек на пульте, AI её не перебивает до новой сцены;
- «Стоп AI» глушит всё, что включил AI, и возвращает музыку в режим подсказок.

Генератор — раздел `music` в `config/show.yaml`:

- `generator: lyria_realtime` — Google Lyria RealTime (экспериментальная модель Google, пока
  бесплатна с квотой; поток проверен на реальном ключе, первый звук через ~3 с, переходы плавные,
  при обрыве — до 3 переподключений): `pip install -e ".[lyria]"`, затем
  `export GEMINI_API_KEY=...` в Терминале перед запуском. Ключ Gemini нужен именно для музыки,
  даже если «мозг» — OpenAI (`OPENAI_API_KEY`);
- `generator: test_tone` — локальный синтезатор аккордов, проверяет цепочку без сети.

Если генератор не отвечает или поток прерывается — плавный переход на файл настроения
(`fallback` у настроения в словаре, например «напряжение» → `music/tension.wav`), а если файла
нет — тишина. Кнопка генератора на пульте переключает генератор/файлы.

Ключи API не храните в файлах репозитория. Бесплатные тарифы Gemini могут использовать присланные
данные для обучения.

## Разработка

```bash
python -m pytest
```

Логика (контроллер, микшер, профили входа, музыка) тестируется без звуковой карты.
